Finding #1 · the dark-mode bug

Every figure loses its meaning in dark mode.

One CSS rule — svg path { stroke: var(--text-secondary) } — repaints every curve in every figure a single grey. The FitzHugh–Nagumo phase plane below has three distinct curves that carry the whole idea. Watch what today's site does to them.

Now — colours collapse to one grey
v-nullcline, w-nullcline and the trajectory are indistinguishable. The figure is technically present, but its information is gone.
After — a themeable colour system
Figures read their colours from theme tokens, so red / teal / amber stay legible and semantic on either ground. Fixed at the root, not patched per-figure.

The rebuild · four phases

How we get from here to there.

Staying vanilla — no build step, no framework — so the same chapters/*.html keep assembling into the 195-page PDF. Interactivity is layered over a static SVG that still prints.

Phase 1

Fix & re-shell

Kill the dark-mode figure bug at the root, replace hardcoded hex with a theme-token figure system, rebuild the CSS shell and typographic scale, wire up the orphaned cover & part-divider pages.

CSS · no risk to content
Phase 2

Figure framework

A tiny vanilla <figure data-widget> convention: canvas widget when JS is on, static SVG when it isn't. One loader, print-safe, reusable across all figures.

JS · progressive enhancement
Phase 3

6–8 hero widgets

Build the flagship interactives — phase plane, AP shape, RK step-size, CFL stability, Nernst/GHK, a propagating wavefront — and convert every remaining figure to the themeable static format.

the headline work
Phase 4

Identity & polish

Cover moment, part openers, refined palette & motion, accessibility & reduced-motion passes, then re-run the PDF build to confirm nothing regressed in print.
