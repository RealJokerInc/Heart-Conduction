# Website UI Audit — 2026-07-03

> Audit of the textbook **website** (`website/`), not chapter content. Content correctness was audited
> 2026-07-02 (`FULL_CHAPTER_AUDIT` / `IMAGE_AUDIT`) and remediated. This audit covers presentation:
> layout, visual identity, typography, dark mode, and the figures as an interactive medium.
> Grounded in live Playwright screenshots (light + dark, title/ch1/ch2/ch10) at 1440×900.

## Verdict

The site is a **competent but anonymous docs template with two real bugs and a wasted opportunity.**
The prose layout (EB Garamond, 3-column, red accent) reads like a real book and is *not* embarrassing in
light mode. What drags it down: (1) dark-mode figures are visibly broken, (2) every figure is a small,
static, hand-drawn SVG that under-uses the page and carries no interactivity, and (3) the whole thing
looks like every other mkdocs/Docusaurus academic theme — no identity for a *cardiac* modeling book.

Overall: **light-mode prose ≈ 3.5/5 · figures ≈ 2/5 · dark mode ≈ 2/5 · visual identity ≈ 2.5/5.**

## Findings (ranked)

### HIGH — Dark-mode figures are broken (correctness bug)
`style.css:811-812`:
```css
[data-theme="dark"] svg line,
[data-theme="dark"] svg path { stroke: var(--text-secondary); }
```
This blanket rule repaints **every** `<line>`/`<path>` in **every** figure to one grey. Confirmed live on
the FHN phase plane (Fig 2.1): the **red** v-nullcline, **blue** w-nullcline, and **green** trajectory all
render as the *same* washed-out grey — the figure's entire semantic color code is destroyed, and the
curves become mutually indistinguishable. This hits every colored figure in dark mode. It exists because
figures hardcode light-mode hex colors, so dark mode "fixes" them with a sledgehammer.

### HIGH — Figures are static, small, decorative, and space-starved
Every figure is an inline SVG with **hardcoded pixel coordinates and hardcoded hex colors**, capped around
`max-width:460px`, centered in a 52em text column → large empty gutters on both sides (visible on Fig 1.1
circuit, Fig 10.x RK diagram). They carry no data and no interaction. For a book whose entire subject is
*dynamics* — phase planes, action potentials, stability regions, wavefront propagation, step-size/CFL
trade-offs — static thumbnails are the single biggest missed opportunity. These are textbook candidates
for explorable widgets (drag the initial condition, move a slider, watch it integrate).

### MED — Generic template identity; one accent color overused
The layout is the default docs three-column (sidebar TOC · justified body · "On this page"). Competent,
but anonymous — indistinguishable from a hundred mkdocs/Docusaurus sites. A single crimson `#e94560` does
*everything*: part headers, active nav, section rules, accent borders, `<mark>` highlights, chapter
labels. No secondary palette, no cardiac motif, no cover moment.

### MED — Cover & part-divider pages are orphaned in the web experience
`title.html` and `part-i…iv.html` exist as files and are assembled into the PDF, but the SPA never loads
them: `toc-part` renders as **non-clickable text** and `allChapters` (app.js:84-95) flattens only
`type:"chapter"` entries. So the website has **no cover / no landing / no part-divider moment** — it drops
you straight into Ch 1 (or last-read via localStorage). Navigating to `#title` silently falls back to Ch1.

### MED — Typography niggles
`p { text-align: justify; hyphens: auto; }` on a serif at ~52em produces loose lines and faint rivers
(visible in Ch 1/10 body). Equation blocks are flat grey boxes with the equation number floated awkwardly
to the top-right, colliding visually with the first line of tall equations.

### LOW — Architecture friction
The SPA loads chapters via `fetch()`, so it **requires an HTTP server** — opening `index.html` from
`file://` shows only the spinner. Right-margin "On this page" is sparse on wide screens. No keyboard hint,
no per-figure permalink/zoom.

## Hard constraint for any rebuild
`website/chapters/*.html` are **double-purposed**: the same files are assembled by
`website/build/html_to_pdf.py` into the 195-pp PDF. Therefore **every figure must keep a static,
print-safe representation** — interactivity has to be progressive enhancement layered *over* a static SVG
fallback, never a canvas-only widget that prints blank. This argues for staying vanilla (no build step)
and enhancing figures in place.

## What's actually good (keep)
- EB Garamond book typography and the overall reading rhythm in light mode.
- Insight boxes (Intuition / Key Insight / Engine Connection / Think About It) — clear, well-colored.
- Working theme toggle, font-size cycle, search, scroll-spy, progress bar, keyboard L/R nav.
- MathJax SVG equation rendering is crisp.
- Clean separation: `toc.json` drives nav; chapters are self-contained fragments.

## Recommended direction (for the plan)
1. **Kill the dark-mode figure bug at the root** — give figures a themeable color system (CSS variables /
   `currentColor` / semantic classes) instead of hardcoded hex, and delete the blanket `svg path` override.
2. **Make the hero figures interactive** — a small vanilla widget layer with static-SVG fallback for print.
3. **Give it an identity + a cover** — real landing page, reachable part dividers, a considered palette and
   a cardiac motif, tightened typography.
4. **Stay vanilla / progressive-enhancement** to preserve the PDF pipeline.
